# 司导与车辆调度管理体系

## 核心流程

1. 游客付款成功后才计入班次报名人数；待付款、取消和退款订单不进入最终配车。
2. 截单后系统根据游客人数自动选择 10、14 座车辆。车辆总座位包含司机，可售游客席分别为 9、13。
3. 系统从“状态可用、车型资质匹配、排班时间覆盖、没有冲突”的司导中自动推荐，每辆车只分配一名司导和一辆实体车辆。
4. 自动结果先成为待确认派单。运营人员可直接更换建议司机或车辆，系统重新校验资格、请假、车检和时间冲突后保存草稿；人工确认前不会通知司导或游客。
5. 20座以上车辆和大巴车先作为手动资源管理，不进入自动派单；实际车辆投入后再启用自动规则。
6. 确认派单后生成本车群组和司导任务；绑定登录账号的司导可在司导端看到日期、路线、车辆、游客人数、集合点和群聊。
7. 行程中记录到达、上车、位置共享和异常；结束后关闭短期定位并保留必要审计记录。

## 总后台首页

- 游客报名：所有未来班次的已付款/已确认席位。
- 已配车辆：当前已确认、执行中的不重复车辆数。
- 出勤司导：当前已确认、执行中的不重复司导数。
- 待配班次：已截单但尚未完成调度，或报名不足需人工决定的班次。
- 安排表：按班次显示日期、几号车、车牌、司导、乘客数/游客席和派单状态。
- 关注中心：报名不足、未配车、派单拒绝/失败、司导未绑定账号、付款履约积压、通知发送异常。
- 订单运行统计：报名中、待配车、已派单、运行中、已完成。

## 权限与安全

- 运营端创建或邀请司导账号，并将账号绑定到唯一的 `driver_resources.account_id`。
- 司导只能看到自己被分配车辆内的履约信息，不可查看付款信息或其他车辆的乘客。
- 系统自动配单不直接发送；必须由运营确认，所有创建、修改、确认、取消操作进入审计记录。
- 每一条草稿记录 `automatic` 或 `manual_override` 来源；已确认任务如需调整，应先取消并填写原因，再生成并确认新方案，避免静默覆盖已公布信息。
- 司机请假、车辆维修、资质过期或时间冲突时不得被自动选中。

## 后续监控建议

- 出发前 24 小时：未配车、司导未确认、游客低于成团线。
- 出发前 2 小时：司机未接受、车辆仍在维修、集合信息未完整。
- 出发前 30 分钟：司机未到达、游客签到异常、关键通知未送达。
- 行程中：司机定位中断、严重迟延、乘客未归队、群聊求助。
- 行程后：行程未正常结束、退款/投诉、位置共享未关闭。
