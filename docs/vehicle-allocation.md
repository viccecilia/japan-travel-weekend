# 车辆分配

Sequential Fill（顺序装载）是不可变业务规则。按运营给出的车辆顺序处理：先使用 Vehicle 1 的剩余客席，满后才进入 Vehicle 2，再进入 Vehicle 3。新订单先填已有未满车辆；已经创建或装满的车辆保持原车型，不能为了容纳新订单改成更大的车型。

配车冻结前先执行车辆组合优化：根据最终报名人数、车型可售客席、当天可用数量与集中成本参数选择总成本最低的组合；成本相同时优先车辆更少，再优先空席更少。组合确认后才执行 Sequential Fill。示例目标为 6人Alphard、12人Hiace、20人Coaster、50人大巴、70人大巴加Coaster。该优化不改变冻结后“不重排已满车辆”的规则。

每个分配产生独立 groupId，一车一群。超过本批车辆总客席的座位返回 `unassigned`，必须由运营追加车辆或阻止确认，禁止超卖。公开页面不得把 80% 内部目标当作剩余座位。

远程测试库的 011 迁移提供仅 service-role 可执行的原子配车函数：锁定 Departure、汇总 paid／confirmed 订单、按集中车型顺序创建 Vehicle Assignment、Vehicle Group 和冻结 Trip Room，再把整张同行订单放入最早可容纳的车辆。当前模型不静默拆分同行订单；如果某张订单无法完整进入任何已创建车辆，整次事务回滚并交由运营调整车型。已有计划不会自动重算或升级车型，重复执行会明确拒绝。
