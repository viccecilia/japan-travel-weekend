# 账户认证与邮件接入门槛

## 当前本地实现

- 正式账户使用 Supabase SDK 会话；未配置公开客户端时关闭注册、登录、重置密码和账户读取，不回退到演示账户。
- 注册确认邮件只能返回当前站点的 `/app/auth/callback`，密码重置邮件只能返回 `/app/reset-password`。应用 origin 必须是无路径、查询和片段的 HTTP(S) origin。
- 回调页只读取 SDK 已建立的会话，不读取 URL 中的自定义 token；后续跳转统一经过 `safeReturnTo`，仅允许批准的 `/app` 内部路径。
- 密码规则集中配置为至少 12 位，并同时包含大写字母、小写字母和数字。服务条款及隐私政策必须勾选后才能提交注册。
- 忘记密码始终返回相同说明，不显示邮箱是否存在。服务端和邮件供应商也必须采用相同的防账户枚举策略。
- 会话恢复完成前，私有页面只显示加载状态。SDK 报告会话失效或退出后，内存用户立即清除，私有路由返回登录页。退出不会删除账户、订单或其他服务器数据。
- development 模式也不会伪装发送邮件；没有已配置 Supabase 邮件能力时明确显示不可用。

## 安全验收重点

- 浏览器只持有允许公开的 Supabase URL 与 publishable key，任何 service-role、SMTP 或供应商秘密不得进入前端构建。
- 注册/重置接口响应和 UI 文案不能泄露账户是否存在。
- 外部 URL、协议相对 URL、登录页循环和非 App 页面均不能成为 `returnTo`。
- 密码修改由已验证的恢复会话调用 SDK；无会话、过期会话和错误回调必须失败关闭。
