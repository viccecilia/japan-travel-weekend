# 上线前外部运维演练记录

本文件定义当前无法仅靠仓库自动测试证明的发布门禁。每次演练都必须记录测试环境、操作者、开始／结束时间、证据链接、实际恢复结果和复盘结论。没有记录等同未执行。

## 监控与告警

- 每分钟探测 `/health` 和 `/ready`；`/ready` 非 200、超时或连续失败必须告警。
- 人为停用一个测试依赖或测试服务，确认告警到达批准的值班渠道并由值班人确认。
- 恢复后确认告警自动关闭，服务日志不包含密钥、乘客资料或支付载荷。
- 记录发现时间、通知时间、确认时间和恢复时间；未批准供应商前不得建立付费告警账户。

## 备份与恢复

- 使用独立、无生产数据的 Supabase 测试项目作为恢复目标；若创建项目要求付款方式，先暂停确认。
- 保存迁移账本、数据库备份和 Storage 对象清单；备份不得提交 Git 或复制到聊天。
- 将备份恢复到独立项目，按 001–020 版本核对迁移，再运行只读结构验收和权限负面测试。
- 核对订单、库存锁、支付事件、Vehicle Group、消息、签到和登车摘要数量；不得使用当前运行项目覆盖式恢复。
- 删除恢复项目之前保存脱敏证据和恢复点／恢复时间结果。

## 容量与安全

- 业务先批准目标：同时在线乘客、每分钟 Checkout、每车消息频率、位置更新频率和可接受延迟。
- 只在测试环境按目标逐级压测；任何错误率上升、Supabase 限额或可能费用出现时立即停止。
- 独立安全审查至少覆盖认证、RLS、越权、Webhook 重放、库存并发、二维码泄漏、文件上传、CORS／CSRF、日志和秘密管理。
- 高／严重问题必须修复并复测；中风险由负责人书面接受后方可继续。

## 正式批准

- 运营确认真实班次、价格、库存、集合地址、车辆、工作人员、取消退款规则和紧急联系人。
- 法律／合规确认隐私、条款、运输许可、保险、图片授权、无障碍陈述和数据保留删除规则。
- 财务确认 Stripe 生产商户、银行卡转账核账、手续费、退款、拒付和对账责任。
- 所有门禁均为 PASS 后，用户另行明确批准移除 noindex、生产只读和生产写入；三步不得合并。
