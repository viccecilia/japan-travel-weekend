# Japan Travel Weekend 真人式验收方案（2026-08-31）

## 目标

以真实用户的点击顺序验证 Web、乘客 App、工作人员端和关键响应式布局，并留下可复核的操作记录、截图节点和缺陷清单。

## 测试环境

- 本地地址：`http://127.0.0.1:5173`
- 浏览器：Codex 内置浏览器，保持可见
- 数据：仅使用本地开发数据与虚构测试资料
- 禁止：真实收费、真实外部消息、真实乘客资料、绕过登录权限

## 测试层次

1. Web 公共页面：主页、路线、私人团体、法律页面及 App 入口。
2. 乘客流程：路线 → 班次 → 座位 → 登录门槛 → 乘客资料 → 结账 → 我的行程。
3. 工作人员流程：登录门槛 → 今日/未来任务 → 付款资格 → 点名/群聊入口。
4. 响应式：320、375、768、1280 像素；检查横向溢出、底部遮挡、触控尺寸和正文可读性。
5. 技术状态：控制台错误、失败请求、路由错误、空链接和生产构建。

## 判定标准

- PASS：核心任务可以继续，显示内容与权限符合预期。
- FAIL：无法完成核心任务、泄露越权信息、误导为真实库存/位置/付款。
- WARN：可以继续但存在文案、布局、可用性或测试数据问题。
