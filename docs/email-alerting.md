# 测试环境邮件告警

Japan Travel Weekend 测试 API 使用 SMTP 发送异常和恢复邮件。健康检查连续失败三次后发送一次异常告警；恢复后发送一次恢复通知并关闭事件。告警邮件只包含环境、服务、状态、失败次数和时间，不包含旅客资料、订单资料或任何密钥。

## 安全配置

SMTP 凭据只允许写入 VPS 上权限为 `600` 的未跟踪环境文件，不得使用 `VITE_` 前缀，也不得写入 Git、浏览器或聊天记录。必需变量列在 `.env.example`。默认 `JTW_EMAIL_ALERT_ENABLED=false`，因此没有完整凭据时不会尝试外发。

推荐使用专门的测试发件邮箱，例如 `alerts@japan-travel.info`。接收地址与发件地址分离。SMTP 使用 TLS；端口 465 时配置 `JTW_SMTP_SECURE=true`，STARTTLS 端口 587 时配置为 `false`。

## 送达规则

- `alert`：连续第三次失败时发送；事件打开后不重复轰炸。
- `recovery`：已打开事件首次恢复时发送。
- 发送失败或尚未配置：不提交状态变化，下一次探测继续尝试发送，避免静默丢失。
- 发送成功：提交事件状态；日志只记录 `delivered`、`failed` 或 `not_configured`，不输出 SMTP 用户名、密码和收件地址。

## 验收

1. 使用测试邮箱配置 SMTP，不使用真实旅客资料。
2. 运行三次受控失败探测，确认只收到一封异常邮件。
3. 恢复健康探测，确认收到一封恢复邮件。
4. 记录检测、发送、收到和人工确认时间。
5. 删除临时合成状态并恢复真实健康探测。

在真实送达演练完成前，启动门禁仍保持 `test_pending`。
