# 将路线内容包接入当前项目

请先读取当前项目的 AGENTS.md 和已有路由、路线数据及图片使用方式，再读取本文件、routes.zh-CN.json、photo-manifest.json、03-待补照片与确认事项.md。

目标：更新/补充这9条路线的中文营销文案、景点卡片及图片。先检查现有项目，不凭本包重建项目，也不按内容包ID覆盖已有业务ID。

1. 根据名称、原有路线和referenceProductId建立映射。已有路线保留业务ID、价格、库存、订单关联、预订链接；新增第9条作为红叶专题草稿。所有路线publicationStatus为draft，因为实际行程尚未核对。
2. 若images目录尚无图，在网络允许的开发环境运行 python download_photos.py。下载失败时报告失败清单；不要绕过网络权限，不要擅自使用搜索缩略图或其他景点照片。脚本只依赖Python标准库，不需安装包。
3. 下载完成后打开preview.html逐张核对地点、画面、季节、取景点和清晰度，再使用。photo-manifest是候选清单，photo-download-report.json才是下载结果。只有状态downloaded且人工或Codex视觉核对通过的图片可接入。不要把待下载路径当成真实存在文件。
4. 原图保留在素材包内；项目使用生成的WebP/AVIF适配图，建议640/1280/1920宽，不放大原图。图片处理使用项目已有能力，若裁剪需记录改动。竖图不要强行裁成失去主体的横封面。卡片固定比例、合理object-position，首屏主图优先，其余懒加载；手机端正文易读。
5. 按routes和attractions接入中文标题、简介、景点文案。其他语言按现有i18n流程处理，不把中文静默写入外语字段。把shared attraction用于重复景点；不复制业务逻辑。
6. 保存photo-credits.json内的作者、来源和许可，网页提供可访问的图片署名信息；遵守每张图实际许可及修改标记。不要仅写“来源网络”。不得把许可字段删掉以省事。
7. 没有照片的景点保留现有已确认图片，或在编辑状态显示待补；不要给上线页面制造破图。现代琵琶湖露台图、宇治甜点图以及未明确的温泉/市场/海岸/游船需单独补齐。不得用不符地点的图凑数。
8. 核对各线路票费、设施、时间及天气限制后才移除草稿标记。贵船/三千院/岚山写为红叶季专题，不承诺满山红叶或未经安排的夜间点灯、川床、小火车。第7条岚山突出竹林，第9条突出秋日山水。
9. 运行项目已有类型检查与构建，检查所有引用图片存在、9条内容映射无重复、移动端卡片不截断。完成后提供修改文件清单、预览方式、仍缺素材与营业确认项。不自动发布生产站。

本包没有改动任何现有项目。无需先征求常规实现细节，可按项目惯例完成可预览的改动。
